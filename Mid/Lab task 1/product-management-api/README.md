# Product Management API — Lab Task 1

A NestJS REST API for a small shop. It manages **products** and **employees**, with create, read, update and delete operations stored in a **PostgreSQL** database through **TypeORM**.

## Tech Stack

- NestJS 11 (TypeScript)
- TypeORM 0.3
- PostgreSQL
- class-validator for validating request bodies

## Prerequisites

- Node.js v20 or later
- PostgreSQL 14 or later (installed locally or run with Docker)
- pnpm 10 (`npm i -g pnpm@10`), or npm

## Database Setup

**Option A: local PostgreSQL**

```bash
psql -U postgres -c "CREATE DATABASE product_management;"
```

**Option B: Docker**

```bash
docker run -d --name product-management-db \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=your_db_password \
  -e POSTGRES_DB=product_management \
  -p 5432:5432 postgres:16-alpine
```

## Installation & Run

```bash
# 1. Install dependencies
pnpm install            # or: npm install

# 2. Create your local env file and set your DB credentials
cp .env.example .env    # then edit DB_USER / DB_PASSWORD / DB_DATABASE

# 3. Create the tables (products, employees)
pnpm migration:run      # or: npm run migration:run

# 4. Start the server
pnpm start:dev          # development (watch mode)
# or
pnpm build && pnpm start:prod
```

The API runs at `http://localhost:5001` (set by `PORT` in `.env`). Swagger docs are at `http://localhost:5001/api`.

> **Note:** the lockfile was created with pnpm 9/10. If you have pnpm 11 or newer, run `npx pnpm@10 install`.

## Environment Variables

Copy `.env.example` to `.env`. The variables that matter for this project are:

| Variable      | Example              | Description           |
| ------------- | -------------------- | --------------------- |
| `PORT`        | `5001`               | HTTP port             |
| `DB_HOST`     | `localhost`          | PostgreSQL host       |
| `DB_PORT`     | `5432`               | PostgreSQL port       |
| `DB_USER`     | `postgres`           | PostgreSQL user       |
| `DB_PASSWORD` | `your_db_password`   | PostgreSQL password   |
| `DB_DATABASE` | `product_management` | Database name         |

The config loader also requires `JWT_BEARER_SECRET` and the `MAILER_*` keys to exist. The `MAILER_*` values can be left empty.

## API Endpoints

### Products

| Method | Endpoint        | Description                     |
| ------ | --------------- | ------------------------------- |
| POST   | `/products`     | Create and save a product       |
| GET    | `/products`     | Return all saved products       |
| GET    | `/products/:id` | Return the product with the ID  |
| PATCH  | `/products/:id` | Update the product with the ID  |
| DELETE | `/products/:id` | Delete the product with the ID  |

Product fields: `id` (generated by the database), `name` (string), `category` (string), `price` (number), `quantity` (integer).

Example body for `POST /products`:

```json
{
  "name": "Wireless Mouse",
  "category": "Electronics",
  "price": 1250.5,
  "quantity": 40
}
```

Example body for `PATCH /products/1` (send only the fields to change):

```json
{
  "price": 1199,
  "quantity": 35
}
```

### Employees

| Method | Endpoint         | Description                      |
| ------ | ---------------- | -------------------------------- |
| POST   | `/employees`     | Create and save an employee      |
| GET    | `/employees`     | Return all saved employees       |
| GET    | `/employees/:id` | Return the employee with the ID  |
| PATCH  | `/employees/:id` | Update the employee with the ID  |
| DELETE | `/employees/:id` | Delete the employee with the ID  |

Employee fields: `id` (generated by the database), `name`, `email`, `phone`, `password` (dummy), `age` (integer), `yearsOfWorking` (integer).

Example body for `POST /employees`:

```json
{
  "name": "Rahim Uddin",
  "email": "rahim@example.com",
  "phone": "01711000000",
  "password": "dummy123",
  "age": 28,
  "yearsOfWorking": 4
}
```

The `password` is saved in the database but is never included in API responses.

### Responses

- `201 Created`: the saved record, including its generated `id`
- `200 OK`: the record or list. DELETE returns `{ "message": "Product with id 1 deleted successfully" }`
- `400 Bad Request`: validation failed (missing or invalid fields, unknown fields, or an `id` that is not a number)
- `404 Not Found`: no record exists with that `id`

## Project Structure

```
src/
├─ main.ts                      # bootstrap, global validation pipe, Swagger
├─ app.module.ts                # registers ProductsModule and EmployeesModule
├─ config/database.config.ts    # TypeORM / PostgreSQL connection
├─ database/migrations/         # CreateProductsTable, CreateEmployeesTable
└─ modules/
   ├─ products/
   │  ├─ dto/                   # CreateProductDto, UpdateProductDto
   │  ├─ entities/product.entity.ts
   │  ├─ products.controller.ts
   │  ├─ products.service.ts    # all database operations
   │  └─ products.module.ts
   └─ employees/
      ├─ dto/                   # CreateEmployeeDto, UpdateEmployeeDto
      ├─ entities/employee.entity.ts
      ├─ employees.controller.ts
      ├─ employees.service.ts   # all database operations
      └─ employees.module.ts
```
